## Native acceptance debt and honest limits

- Neither downloaded Mac DMG has passed first-launch Gatekeeper handling, provider discovery,
  course creation, or the ordinary learner path on physical native hardware. The Intel DMG still
  requires its own physical Intel Mac run. One architecture cannot accept the other.
- The downloaded Windows installer has not passed an isolated `0.0.9` to `0.0.10` in-app update.
  An installed learner-path check should also cover course-folder slugging, first-module part
  progress, command approvals, and the update status-bar, toast, and dialog flow.
- No exact `0.0.10` downloaded package has completed uninstall and learner-data preservation checks.
- The Windows installer is intentionally `NotSigned`, and the Mac packages are unsigned and
  unnotarized. The app-owned Ed25519 manifest protects update selection and package bytes but does
  not remove SmartScreen or Gatekeeper warnings.
- The release is public and is the current `releases/latest` target. The maintainer explicitly
  authorized end-to-end publication after protected native package verification and downloaded-byte
  integrity acceptance. The missing installed Windows and separate physical Mac checks remain
  post-publication debt and must not be reported as passed.
