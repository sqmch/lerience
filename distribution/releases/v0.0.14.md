# Lerience 0.0.14

You can now steer a Codex tutor mid-turn instead of waiting for it to finish, and your session
choices stay put across a course. Generated modules are reviewed from the learner's side before
handover, and four defects found in a real course run are repaired.

## Added

- Send a message into a running Codex turn. A message typed while the tutor is working is taken
  into the turn in flight; the model sees it at its next step rather than instantly, and the
  composer says so. Claude Code has no equivalent method, so a message typed during a Claude turn
  still queues and sends when the turn finishes. The app reports which behaviour applies rather
  than assuming one.
- Remember session controls per course. Model, effort, autonomy including "Never ask", and Codex
  access including "Full access" are remembered for each course and provider, and re-applied when
  a tutor runtime starts. A restored control reads "· remembered" until you change it, and
  choosing the provider default forgets it. Nothing is written to provider settings, and the
  remembered values live in application data rather than in the course folder, so an access grant
  never travels with a course.

## Changed

- Update the bundled Course Engine to 0.2.0. Before a module is handed over, a reader without the
  tutor's context reviews it from the learner's side and records what it found; module QA requires
  that review and cross-checks the brief against the scaffold's answer file, flagging placeholders
  that lie about their type and answer fields the brief never names. Sealed hint files retire in
  favour of live assistance about the actual stuck point; the three assistance levels keep their
  meanings. Course format stays at version 0.
- Repair four defects found while working through a real course: the lab overlay's visualization
  switcher opened underneath the overlay and could not be clicked; the course track's progress bar
  read 100% at the end of the first module because modules are generated just in time and no
  honest denominator exists, so the header keeps the count and drops the bar; module length printed
  as `0.75h` instead of 45 minutes, and the scaffold's runtime tag no longer reaches the track; and
  dark-theme headings sat too close to body text to separate from it.
- Clear every dependency advisory reported at moderate and above. No packaged runtime input and no
  provider code changed.

## Upgrading

Existing courses keep the Course Engine files they were created with and are unaffected by the
0.2.0 engine change until an explicit engine update. Session controls start unremembered; the
first choice you make in a course is the one that is kept.

## Known limitations

- The desktop packages do not yet carry trusted operating-system signatures. Windows may show an
  unknown-publisher or SmartScreen warning. On macOS, the first launch must be approved under
  System Settings > Privacy & Security.
- macOS uses separate Apple Silicon and Intel downloads. Both native packages are built and checked
  independently by the release workflow. The Intel package has no physical Intel Mac acceptance run.
- Steering requires a Codex App Server that offers `turn/steer`; the supported minimum is unchanged
  from the previous release. Steering a Codex turn and restoring remembered controls have passed
  deterministic tests but have not yet been exercised against a live provider session; both are
  pending native acceptance.
- Tutor clients remain separately installed and authenticated. Lerience does not install or update
  Codex or Claude Code.
- The learner's-side review is a new handover requirement. Whether it catches comprehension defects
  that automated checks cannot see is evidence a real course run has to provide.
