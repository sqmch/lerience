# Lerience 0.0.12

This release makes module creation easier to follow, gives learners reliable control over Codex
permissions, strengthens the Course Engine's teaching evidence, and introduces Lerience's new mark.

## Changed

- Show all seven module parts from the start, refresh progress from the published course inventory,
  and let learners expand long streamed build output.
- Wait for the selected tutor's actual permission options before module creation begins. Codex now
  offers explicit Course folder and Full access choices, and Never ask reliably suppresses approval
  prompts for the active session.
- Make packaged Windows npm and npx launchers work consistently from PowerShell, Command Prompt, and
  Git shell without relying on a separate Node installation.
- Update the bundled Course Engine to 0.1.1. New courses teach coherent work blocks, check important
  claims against versioned sources, and require an independent explanation plus a small changed
  example before completion. Course format 0 and existing courses remain unchanged.
- Replace the application, installer, title-bar, and repository marks with one exact geometric mark.
  The repository front page now puts installation and the course view up front.

## Known limitations

- The desktop packages do not yet carry trusted operating-system signatures. Windows may show an
  unknown-publisher or SmartScreen warning. On macOS, the first launch must be approved under
  System Settings > Privacy & Security.
- macOS uses separate Apple Silicon and Intel downloads. Both native packages are built and checked
  independently before publication.
- Tutor clients remain separately installed and authenticated. Lerience does not install or update
  Codex or Claude Code.
- Existing courses keep the Course Engine files they were created with. Lerience does not silently
  replace a learner's course protocol.
